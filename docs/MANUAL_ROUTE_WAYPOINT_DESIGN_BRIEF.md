# 子线手动改线与可选择途径点设计简报

最后更新：2026-08-24
状态：历史设计，已由 KD-076 与 Schema v21 统一节点模型取代

> 演化说明：本文件保留 Schema v17–v20 途径点/分流节点双模型的历史背景。当前运行版本已由 KD-076 与 Schema v21 统一为“节点”，并支持节点双击起线；有效方案见 `UNIFIED_CONNECTION_NODE_DESIGN_BRIEF.md`，本文件中的旧字段和入口限制不再约束当前实现。

## 1. 功能目标

在保留自动正交路由为默认行为的前提下，允许用户通过拖动任意普通子线段表达明确的走线走廊。系统不保存整条 SVG 或折线结果，而是保存少量途径点约束；路由器继续负责端点附着、8px 正交、避障、共线占用、拱桥和确定性评分。

该增量解决两个问题：用户可把自动线路挪到指定位置；后续移动或旋转相关图元时，系统仍能依据稳定约束重新求解，而不是依赖脆弱的完整手绘路径。

## 2. 核心交互

1. 选中逻辑子线或共享主干后，画布渐进显示其途径点和可拖动线段反馈，不新增常驻工具栏或独立“手动布线模式”。
2. 任意普通子线段都可沿自身法向平行拖动，包括靠近源端或目标端的线段。拖动落在 8px 网格，并实时预览新的正交路径。
3. 拖动一段线路，本质上是在该段两端创建或更新一对有序途径点；路由器自动补齐端点到途径点、途径点之间及途径点到终点的正交过渡。
4. `Esc` 取消当前拖动并恢复手势开始前状态；合法结果在松手后作为一个历史事务提交，撤销/重做一次还原整次操作。
5. 途径点出现后可像轻量几何对象一样单独选择、移动和删除；`Shift` / `Ctrl` / `Command` 可追加选择，途径点显示时也可被框选。

## 3. 数据模型与拓扑边界

当前已在图纸级保存规范化途径点，逻辑边只保存有序引用：

```ts
type RouteWaypoint = {
  id: string;
  x: number;
  y: number;
};

type Diagram = {
  routeWaypoints?: RouteWaypoint[];
};

type ConnectionEdge = {
  routeWaypointIds?: string[];
};
```

- 路由顺序为源端点 → 有序途径点 → 目标端点；每一段继续交给现有自动路由器求解。
- 普通途径点是显示路径的硬几何约束，不是连接节点、分叉点或母线 tap；不能从途径点起线。只有接线明确落到该点，或途径点与其他途径点/分流节点精确碰撞时，系统才把它提升为真实拓扑分流节点并移除对应几何约束。
- 普通途径点不参与 Source/Target、Switch 门控、单向通行或流动动画拓扑计算；真实分流节点只连接邻接物理边，仍不成为 Source、Target 或门控设备。
- 项目只持久化途径点约束，不持久化完整 polyline、SVG path、自动折点或派生分叉。

## 4. 共享线段与共享途径点

- 拖动多条逻辑边共同经过的显示线段时，系统精确找出当前使用该段的全部逻辑边，并创建或更新一对共享途径点。
- 这些逻辑边引用相同的途径点 ID；移动共享途径点会同时改变所有引用线路，选中反馈显示“共享途径点 · N条子线”。
- 首版不支持把某一条逻辑边从共享途径点中单独拆离。如需独立走线，先删除或恢复相关共享约束，再在独立支路上重新拖动。
- 删除共享途径点对所有引用它的逻辑边一起生效；删除和引用清理组成一个可撤销事务，不残留部分引用。

## 5. 选择、移动与旋转

- 途径点可单选、多选，也可与图元和母线组成混合选择。
- 混合选择移动时，已选途径点与图元、母线使用同一平移量；未选途径点保持绝对画布坐标不变。
- 混合选择旋转时，已选途径点与其他对象共同绕选区中心按 90° 步进旋转，并重新贴合 8px 网格。
- 首版只要选区包含途径点，就不提供整体缩放，避免点坐标、图元离散缩放和线路约束产生含糊语义。
- 复制、Duplicate 或跨图纸复制时，仅当途径点所约束的逻辑边属于选区内部复制拓扑，才复制对应途径点并生成新 ID；副本随整体平移或旋转保持相对位置，外部支路和仅被外部线路引用的点不复制。

## 6. 冲突处理

- 途径点是硬约束。图元或母线的移动、旋转、缩放在提交前必须以候选几何预检所有受影响线路。
- 若任何受影响线路无法同时满足端点方向、途径点顺序、正交网格、图元避障和占用约束，则取消整个对象变换，不做部分提交。
- 多选操作只显示一条汇总 Toast，不按线路连续弹出。建议文案：`无法移动：3 条线路的手动途径点约束发生冲突`；可补充“请同时选择相关途径点，或先恢复自动布线”。
- 若途径点与对象一起被选中，其候选位置随对象共同变换后再参与预检，因此用户可以通过整体移动或旋转保留手动走线关系。
- 拖动途径点自身若无合法解，画布保留无效预览提示，松手后回到原位置且不写历史。

## 7. 删除与恢复自动布线

- 删除选中的普通途径点时，从其引用逻辑边的有序列表移除；删除共享途径点时，从所有引用逻辑边中一起移除。
- 选中一条或多条逻辑子线后，右侧属性面板提供“恢复自动布线”；执行后清除所选边的全部途径点引用，并立即按现有自动路由规则重算。
- 若共享途径点仍被未纳入本次操作的其他逻辑边引用，则实体保留；最后一个引用消失后自动回收孤立途径点。
- 删除途径点、批量恢复自动布线、引用清理和孤立点回收分别作为完整单事务进入撤销/重做。

## 8. 路由、Worker 与数据生命周期

- 没有途径点的线路继续完全遵循现有最短长度、完整转折和中点优先评分；途径点只把整条路由分解为多个必须依序经过的自动路由区间。
- 正式 Web Worker、主线程降级路径和交互预览必须使用相同的途径点约束语义；任一途径点变化会把所有引用边及受其占用走廊影响的网络标记为脏。
- 网络合并或拆分时保留逻辑边上的途径点引用；删除逻辑边、网络、图元或母线后清理失效引用，并回收不再被任何边引用的途径点。
- 项目 Schema 已在途径点首版从 v16 升至 v17，并在真实分流节点首版由 v18 升至 v19；v16 及更早项目缺省没有途径点，v6–v18 项目缺省没有真实分流节点，载入后保持既有自动路由结果与编辑行为。v1–v5 旧固定分叉继续按既有规则迁移为端点逻辑关系，不恢复旧坐标语义。

## 9. 首版边界

- 支持所有普通子线段拖动，不支持直接拖母线本体来创建途径点，也不把拱桥圆弧当作可拖线段。
- 途径点默认不承担业务分叉、任意中段标签锚定或运行态数据；它只可作为接线落点被提升为真实分流节点，首版不能主动起线。
- 首版不支持从共享途径点拆出单条边、不支持含途径点选区整体缩放，也不自动放松或静默删除冲突约束。
- 视觉保持当前中性、克制、画布优先的系统风格；未选线路不常驻显示途径点，避免大图产生额外噪声。

## 10. 兼容子线接入与真实分流节点

- 接线仍从图元锚点或母线发起；进行中 hover 兼容子线时，仅在吸附到的 8px 显示段位置出现空心圆提示，点击后创建或复用真实分流节点。子线、途径点和分流节点首版均不能主动起线。
- 落点位于共享显示段时，系统拆分所有实际经过该原子段的逻辑边，不要求用户选择某一条隐藏的底层边；新支路与拆分后的主管边共同引用一个 `junction` 节点。
- 分流节点不显示常驻标记，编辑态 hover 才显示圆点；可单选、追加、框选、移动、方向键步进、删除，也可与图元、母线和途径点共同移动或 90° 旋转。含分流节点的混合选区不缩放。
- 删除分流节点会删除全部邻接边，包括原主管拆出的两半，不自动补回拆分前的直连边；删除、网络规范化、途径点回收和历史写入是一个事务。
- 同一 8px 坐标上的途径点和分流节点自动合并为一个真实分流节点；线路类型不能解析为同一类型时取消整次操作并显示一条汇总 Toast。
- 拆边保留颜色与单向通行；源侧半边沿用原边 ID，目标侧半边使用新 ID，标签只保留在原配置端点所在半边。监控动画沿拆分后的全部有效物理边连续通过分流节点。
- 复制、Duplicate 或跨图纸粘贴只复制选区内部端点之间仍成立的分流子树，生成新节点/边 ID 并按副本偏移平移节点；连向选区外对象的分支被剪除。

## 11. 验收标准

- 任意普通子线段可平行拖动并形成稳定的 8px 正交路径，靠近端点的线段也不例外。
- 途径点可被单选、追加选择、框选、移动和删除；与图元/母线混合移动或旋转时保持相对几何并能一次撤销。
- 共享主干拖动只影响实际使用该段的逻辑边；共享点移动和删除对全部引用边一致生效。
- “恢复自动布线”能清除所选逻辑边的手动约束；仍被其他边引用的共享点不误删，孤立点自动回收。
- 约束冲突时整次对象变换被阻止，只出现一条汇总 Toast，项目、历史和线路几何均不发生部分修改。
- 保存/重载、JSON 往返、复制/Duplicate、跨图纸复制、网络拆分以及 Worker 重路由后，途径点引用与显示路径保持确定且无孤立数据。
- 单向通行、Source/Target、Switch 门控和流动动画的业务拓扑不因途径点而改变；动画沿新的受约束显示路径连续绘制。
- 从兼容图元锚点或母线起线可落到独立支路或共享主干；hover 只显示临时圆点，提交后无常驻标记，流动动画穿过全部有效分支。
- 分流节点可被单选、追加和框选，并能与图元、母线或途径点共同移动/旋转；同点自动合并，类型不兼容或路由无解时整次回滚并只显示一条 Toast。
- 删除分流节点后全部邻接边一起移除且不恢复主管直连；撤销可一次恢复节点、拆分边、标签/颜色/方向及相关途径点。
