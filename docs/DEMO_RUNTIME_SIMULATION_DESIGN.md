# 可移植拟真演示运行时设计简报

状态：核心实现完成，待用户验收
最后更新：2026-09-03

## 1. 功能摘要

为编辑器内监控模式和跨项目 `RuntimeBundleViewer` 提供同一套、零配置、可重复的拟真演示运行时。系统不再让每个指标独立随机跳值，而是从统一设备状态、页面负载和冷却/电力拓扑生成设备状态、运行数据、告警等级与流动动画，使领导演示中的数值和链路表现彼此一致。

本阶段只追求“视觉和业务关系可信”，不宣称电气潮流、水力、热力或保护整定的工程计算精度。演示档案中的范围是常见 AIDC 场景的保守默认值，不得作为现场告警阈值、验收标准或设备选型依据。

## 2. 首要用户任务

用户导出一组图纸并在当前项目或另一个 React 项目打开后，无需连接遥测或重新配置，就能稳定看到：

- 大多数设备正常运行，电流与水流沿有效链路连续运动；
- 每张包含可模拟设备的非空图纸只有极少数异常，且异常数据、设备状态和动画结果互相解释得通；
- 同一个运行包在不同机器、刷新或重新进入页面后仍呈现同一组演示故障，便于按固定讲解顺序演示；
- 播放后数值缓慢变化，但不会在讲解过程中突然把异常转移到另一台设备或自行恢复。

## 3. 设计方向

- 画布和拓扑继续是第一视觉层级；不新增占据画布的大型仪表盘。
- 正常、异常、离线和开关/运行状态是相互独立的维度，避免把“正常停机”错误显示成告警。
- 所有运行信息从一个快照生成，禁止指标、泵阀状态和动画各自随机。
- 演示场景确定、可回放、可导出；只有时间曲线缓慢变化，异常对象和故障类型保持稳定。
- 设备类型档案优先于历史手工模拟范围；旧配置仍保留用于编辑兼容和无档案回退，但不再决定标准演示场景。

## 4. 统一运行状态模型

### 4.1 三层状态

| 层 | 取值示例 | 职责 |
| --- | --- | --- |
| 健康状态 `health` | `normal`、`minor`、`major`、`critical`、`offline` | 决定数据告警、离线表现和故障语义 |
| 运行状态 `operation` | `running`、`standby`、`stopped`、`open`、`closed`、`charging`、`discharging` | 表达设备当前工作方式，不自动等于异常 |
| 链路状态 `flow` | `energized/deenergized`、`flowing/no-flow`、方向、强度 | 由拓扑和设备状态派生，驱动电流/水流动画 |

必须满足：

- Switch、2WV、CV 的 Off/Closed 可以是正常操作状态，不因关闭本身产生黄色或红色异常。
- 水泵正常停机和水泵离线是不同状态；两者都停流，但离线应显示无数据或通信异常。
- 设备异常不一定停机；例如温度偏高时仍可保持运行和流动。
- `critical` 只有在故障类型要求切断、跳闸或停泵时才中断链路，不能把所有红色数据一律转成停流。

### 4.2 统一快照

演示 Provider 每个采样时刻只生成一个 `RuntimeSnapshot`，至少包含：

```ts
interface RuntimeSnapshot {
  timestamp: number
  source: 'demo' | 'telemetry'
  devices: Record<ElementId, {
    health: 'normal' | 'minor' | 'major' | 'critical' | 'offline'
    operation: DeviceOperation
    online: boolean
    faultCode?: string
  }>
  metrics: MonitorMetricReadings
  electrical: ElectricalRuntimeInputs
  cooling: CoolingRuntimeSnapshot
  events: RuntimeEvent[]
}
```

电力拓扑、冷却拓扑、指标标签和 WebGL 流动层必须消费同一个快照。现有独立 `MonitorMetricDataProvider` 与 `CoolingRuntimeProvider` 在迁移期通过适配器继续可用；新演示入口不得再分别实例化互不相关的随机 Provider。

## 5. 确定性演示场景

### 5.1 固定种子与相对时钟

运行包保存 `seed`、`algorithmVersion`、`profileVersion` 和相对场景起点。设备异常分配使用 `bundleId + diagramId + elementId + seed` 的稳定散列，不依赖数组顺序、浏览器随机数或本地时区。

- 同一 Bundle 与种子：异常设备、故障类型、严重度和初始值一致。
- 播放：场景时钟前进，正常值和异常值在所属区间内缓慢漂移。
- 暂停：数据时钟与动画同时冻结。
- 重新进入页面：恢复到同一相对场景时刻，不重新抽取异常。
- 刷新或迁移到另一宿主：根据清单重建相同场景，不需要保存每帧读数。
- 当前监控面板的人工运行态覆盖优先于演示快照，清除覆盖后恢复演示状态。

### 5.2 刷新节奏

- Provider 每 `2–5s` 生成一次轻量运行快照；画面只更新可见标签和必要拓扑输入。
- 数值采用确定性的缓慢曲线、负载趋势与小幅噪声，不再每 30 秒全图同时跳到无关值。
- WebGL 动画仍按帧运行，但 React 不得按帧写运行状态。
- 页面公共负载因子以分钟级缓慢变化，单台设备叠加固定相位和小噪声，避免所有设备同步升降。

## 6. 页面异常预算

### 6.1 数量规则

| 当前图纸可模拟设备数 | 稳定异常数 |
| --- | --- |
| `1–7` | `1` |
| `8–30` | `1–2` |
| `>30` | `2–3` |

- 每张包含可模拟设备的非空图纸至少有 `1` 个可见异常；空图不伪造设备或告警。
- 页面异常占比通常不超过 `5%`，小图因“至少一个”规则可例外。
- Bundle 全局尽量覆盖次要、重要、紧急、离线，以及正常停机/关闭等状态；只有存在适合设备时才分配对应类型。
- 严重度以次要和重要为主，紧急与离线必须稀少；同一页面默认最多一个紧急或离线。
- 优先选择叶端、冗余支路或不会让整页失去主要动画的设备。主供电源、唯一泵和关键上游阀只有在仍能保留可讲解链路时才允许故障。

### 6.2 稳定性规则

异常预算在 Bundle 编译时完成分配，运行时只生成数值曲线，不重新抽签。一次演示会话中异常不会跨设备移动、自动升级、自动恢复或反复闪烁。后续如需“故障演练模式”，应作为独立场景脚本，不混入默认领导演示档案。

## 7. 指标语义与设备档案

### 7.1 语义键

模拟器不再仅依赖指标显示名称判断含义。每个运行指标先绑定稳定语义键，例如：

- 电气：`lineVoltage`、`frequency`、`activePower`、`loadRatio`、`powerFactor`、`soc`、`backupTime`；
- 冷却：`supplyTemperature`、`returnTemperature`、`deltaTemperature`、`pressure`、`differentialPressure`、`flowRate`、`outputRatio`、`valvePosition`；
- 通用：`status`、`communication`、`deviceTemperature`。

Bundle 编译器根据资产键、指标名、单位和同设备其他指标一次性生成 `metricBindings`。首版兼容历史别名和单位：`HZ` 归一到 `Hz`，`m²/h`、`³m/h` 和其他明显历史拼写归一到 `m³/h`；归一只发生在运行清单，不自动改写用户项目。

无法可靠识别的自定义指标使用实例配置回退，但必须采用截断正态分布和稳定曲线，不使用全范围均匀随机。

### 7.2 档案结构

每类设备使用版本化 `DeviceSimulationProfile`：

```ts
interface DeviceSimulationProfile {
  profileVersion: string
  assetKeys: string[]
  role: DeviceRole
  ratedDefaults?: RatedDefaults
  defaultMetrics: MetricProfile[]
  allowedOperations: DeviceOperation[]
  faultModes: FaultModeProfile[]
}
```

每个 `MetricProfile` 定义语义键、显示名、规范单位、精度、正常区间、三级异常区间、额定值来源、允许的运行状态和与其他指标的关系。区间边界按“下界包含、上界不包含”统一处理，最外层可无限延伸。

#### 通用图元与未知设备

通用图元不猜测设备物理类型。它只显示用户已经配置且可绑定的指标；无法绑定时按实例正常区间生成稳定曲线，并把异常值放入用户范围外相邻的严重度带：次要偏离正常边界 `5–10%`，重要 `10–20%`，紧急 `20–35%`。若实例没有任何指标，运行时只可补一个“通信状态”，不得凭空添加温度、功率或压力。

## 8. 指标与故障的关联规则

- 一个异常设备默认只有一个主故障，其余指标按因果关系响应，避免同一设备同时出现五个无关红色数值。
- 高负载可同时抬高电流和温度；电压、频率仍保持小幅稳定，除非主故障就是供电质量。
- 冷却负载升高会提高回水温度和 ΔT，并增加泵输出/流量；不得出现负载升高但供回水温度、流量完全不动。
- 泵性能下降表现为输出较高、流量或压力偏低；阀门卡涩表现为命令开但阀位不足和下游流量降低。
- 通信离线显示 `--`、停止相关流动并降低设备视觉强调；不要伪造一个红色数值代表离线。
- 停机/关闭时功率、流量和相关输出应为 `0` 或 `--`，状态文本保持正常中性；只有非预期停机、反馈不一致或通信失败才产生告警。

## 9. RuntimeBundle 演进

`DiagramRuntimeBundle` 下一版本增加可选 `simulation` 清单：

```ts
interface DemoSimulationManifest {
  algorithmVersion: string
  profileVersion: string
  seed: string
  clockMode: 'relative'
  metricBindings: Record<MetricId, MetricSemanticBinding>
  deviceProfiles: Record<ElementId, DeviceProfileRef>
  anomalyAssignments: Record<ElementId, FaultAssignment>
}
```

清单保存可复现规则，不保存每帧读数、定时器、Provider 实例或 Three.js 对象。`RuntimeBundleViewer` 缺省启用 Demo Runtime Engine；宿主传入真实遥测 Provider 时，真实快照整体取代演示 Provider，而不是只覆盖部分随机值。

旧 v1 Bundle 仍可解析，并在内存中使用当前档案与其内容散列生成兼容种子。新版本导出必须冻结档案版本和异常分配，避免软件升级后同一个已交付 Bundle 的演示设备悄然变化。

## 10. 与项目指标配置的关系

- 项目内既有指标名称、显示顺序、显隐、单位和精度继续决定标签内容与布局。
- 既有手工模拟最小/最大值和三级阈值不自动删除、不批量改写，保证旧项目可编辑、可回退。
- 标准演示模式中，设备档案生成读数与最终严重度，优先级高于历史手工模拟范围；避免错误阈值把正常读数判成异常，或把异常读数判成正常。
- 不认识的自定义指标才回退到实例配置；真实遥测模式仍可由宿主选择使用项目阈值或服务端告警等级。
- 如果图元没有配置档案默认指标，运行时可在内存中补 `1–3` 项最能说明状态的默认指标；补充项不写项目 JSON、不产生 dirty，也不占用用户配置的 5 项上限。编辑模式继续只显示用户配置内容。

## 11. 视觉表达

| 状态 | 图元与标签 | 动画 |
| --- | --- | --- |
| 正常运行 | 既有图元和中性数据 | 按拓扑、方向和强度流动 |
| 次要/重要/紧急 | 图元主体保持可识别；只有异常数据使用既有黄/橙/红底和黑字 | 除故障明确要求切断外继续流动 |
| 离线 | 图元降低饱和度/亮度；数据为 `--`，可显示“离线”状态 | 设备相关电流/水流停止 |
| 正常停机/关闭 | 使用既有 Off/停机素材；功率/流量为 `0`，数据无告警底色 | 对应链路停止 |
| 备用 | 保持中性并显示“备用” | 未投入链路静止，不显示异常 |

异常仍只给数据本身加底色，指标标题与单位保持原样，不增加整块标签背景。图元整体状态效果应克制，避免满画布红色发光抢走拓扑层级。

## 12. 验收与自动化约束

### 确定性

- 相同 Bundle、种子、场景时刻生成逐字段一致的异常分配和允许误差内一致的数值。
- 图元、指标或图纸数组顺序变化不改变已有稳定 ID 的分配。
- 播放暂停冻结数据；刷新和跨宿主恢复同一演示场景。

### 数值与状态

- 每个数值的严重度与设备档案区间一致；边界值按统一包含规则无歧义。
- 正常停机/关闭不产生异常背景；离线不继续显示正常读数。
- 同设备关联指标满足档案约束，上下游聚合值在允许误差内合理。
- 历史 `m²/h`、`³m/h`、`HZ` 可映射为规范语义和单位，但源项目不被自动修改。

### 页面覆盖

- 每张有可模拟设备的非空图纸满足异常预算，且同页最多一个紧急/离线。
- Bundle 全局在设备条件允许时覆盖四级健康状态和至少一种正常停机/关闭状态。
- 异常分配后仍保留可见主电流或主水流；唯一源/唯一泵故障不得让整张演示图完全静止。

### 拓扑一致性

- Off Switch 两侧按既有规则停电；跳闸故障与实际停流区域一致。
- 泵停止、阀关闭、CV 逆向或离线设备不得继续产生水流。
- Cabinet 双路供电继续独立；单路异常时另一有效支路可继续动画。
- 指标刷新不写项目、dirty、编辑历史或 RuntimeBundle 文件。

## 13. 实施顺序

1. **档案与语义层**：建立语义键、历史别名/单位映射、设备档案与范围测试；先覆盖现有场景资产。
2. **统一快照层**：新增 `RuntimeSnapshot` 与旧 Provider 适配器，在不改变画面的前提下让指标、电力、冷却消费同一输入。
3. **确定性引擎**：实现稳定种子、页面异常预算、故障分配、慢速曲线和播放/暂停时钟。
4. **拓扑关联**：实现电力上下游负载聚合、泵阀/流量/温差关系和故障停流规则。
5. **演示补充与视觉状态**：为缺指标设备注入运行时默认指标，补齐离线、备用、正常停机的克制视觉表达。
6. **RuntimeBundle 升级**：导出模拟清单、兼容 v1、在零配置查看器中默认启用，并验证跨宿主复现。
7. **演示验收**：逐页检查异常数量、讲解覆盖、主链动画和数值可信度；视觉结论由用户验收。

## 14. 明确不做

- 不做工程级潮流、水力、热力、保护配合或容量校核。
- 不把演示范围写成现场告警阈值，不自动覆盖用户项目原配置。
- 不让异常按随机定时器频繁出现、消失或换设备。
- 不在 Bundle 中保存高频时间序列或每帧动画状态。
- 不在本阶段接入真实遥测、历史趋势、告警确认或联动控制。

## 15. 实施结果

- 新增 `demoSimulationProfiles.ts`，覆盖当前素材目录全部设备键；按电力、冷却、阀门、机柜、储能和通用设备提供版本化语义、正常区间及三级异常区间。
- 新增 `DemoMonitorMetricDataProvider`：每张非空图纸按设备数稳定分配 `1–3` 个异常，以 `3s` 节拍生成带公共负载趋势和设备相位的缓慢曲线；播放暂停时数据时钟冻结，刷新和 Bundle 迁移可按相同种子复现。
- 已识别设备的运行读数与最终严重度优先使用设备档案；旧手工范围不删除、不改写。`HZ`、`m²/h`、`³m/h`、`℃` 只在运行时规范化；已知设备中明显不适用的历史指标会由运行时默认指标替代。
- 没有指标的普通设备不批量增加标签；只有被分配为异常的设备会在运行态补最多两项默认指标并自动显示，补充内容不进入项目 JSON、Schema、dirty、历史或五项配置上限。
- On/Off、Supply/Load 运行/待机和泵启停已进入模拟输入：正常关闭、待机或停机时功率/流量/负载率为 `0`，阀位使用 `0–5%` 正常带；关闭反馈偏大才按三级范围告警。Supply/Load 的待机是正常运行方式，文本状态显示“待机”，不产生异常；其运行/待机颜色可分别配置，但当前不自动决定 Source/Target 或截断电力拓扑。Schema v35 还把每个水泵的人工启停与输出功率作为项目快照保存，并在 RuntimeBundle 中作为演示缺省值；宿主显式覆盖继续优先。离线设备显示 `--` 并压暗；离线只优先分配给 Cabinet、Battery 等安全叶端/备用设备，避免唯一电源或水泵让整页演示动画消失。
- `useDiagramMonitorRuntime` 以同一 `MonitorMetricRuntimeSnapshot` 中的设备健康、运行方式和读数生成有效运行状态，再派生电力/冷却拓扑、冷却流量覆盖和标签；外部 Provider 接口继续兼容。
- RuntimeBundle 已升级到 v2，保存种子、算法/档案版本、指标语义、设备档案引用和稳定异常分配；其项目文档部分同时携带 Schema v35 水泵启停/输出功率快照，但不保存每帧读数、趋势、时钟或动画相位。v1 仍可解析，`RuntimeBundleViewer` 未注入真实指标 Provider 时零配置启动同一演示场景。
- 自动化覆盖设备档案完整性、页面异常预算、数组顺序确定性、异常范围、历史单位、错误设备指标替换、关闭阀位、Supply/Load 待机归零、离线停泵与人工覆盖、暂停/切页时钟、v1/v2 往返、全局严重度覆盖和监控 DOM。全量 `456` 项测试通过、`1` 项跳过；设计系统契约、TypeScript 和生产构建通过。最终逐页数值观感与动画效果按项目约定由用户验收。
