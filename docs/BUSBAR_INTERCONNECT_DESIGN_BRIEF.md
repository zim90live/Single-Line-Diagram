# 母线普通子线互联设计简报

最后更新：2026-08-14  
状态：已实现，待用户视觉与操作验收

## 1. 功能摘要

电力图纸中的两条不同母线可以通过一条明确可见、可选择和可删除的普通电力接线互联。该线路称为“子线”，它不是母线之间的隐式合并，也不是新的母线类型；只有子线存在时，两条母线才在拓扑上连通。

本增量面向 AIDC 运维人员的高频画布编辑，不新增常驻工具按钮。交互复用普通线路的渐进披露模式：先选择母线，再从母线上的空心候选点发起子线。

## 2. 交互模型

1. 普通点击母线仍执行选择；拖动母线仍执行移动。
2. 母线选中且当前没有拖动时，hover 母线显示距离指针最近的合法 8px 空心起线候选点。
3. 点击候选点进入电力接线状态，临时普通线路随指针正交增长。
4. hover 另一条母线时显示合法目标 tap；点击完成子线并一次提交拓扑变化。
5. 同一母线不能连接自身；`Esc` 或鼠标右键取消，不写入历史。
6. 已完成子线沿用普通线路的选择、删除、撤销/重做和拱桥表现，不新增专用属性面板。

## 3. 数据与拓扑

- 子线使用现有 `ConnectionEdge`，两端各引用一个 `busbar-tap` 节点。
- 两条母线原本位于不同线路网络时，完成子线会合并两个网络；只有一侧已有网络时，把另一条母线接入该网络；两侧均无网络时创建新的电力网络。
- 两条母线已经位于同一网络时，允许在不同 tap 位置创建另一条实体子线，以表达真实的多路连接；完全相同的一对 tap 节点之间禁止重复边。
- 删除子线后通过现有隐式母线邻接重新计算连通分量；若不存在其他路径，原网络自动拆分。
- 该能力在 Schema v5 已能表达“两个 busbar-tap + 一条普通边”；当前 Schema v6 继续沿用，不为母线互联增加额外持久化字段。

## 4. 双端 tap 自动路由

- 子线两端 tap 都是可沿所属母线滑移的变量，不能按两个单端 tap 顺序独立求解。
- 路由器联合比较两条母线上的合法 8px tap 组合，先满足避障、正交、禁止共线、拱桥点禁接入和不同母线等硬约束，再依次最小化总长度、总转折、两端相对原始点击位置的总滑移距离，并用稳定 offset 顺序破同分。
- 水平母线只能从垂直方向离开或进入，垂直母线只能从水平方向离开或进入；母线自身占用边继续作为共线障碍。
- 普通线路与母线或其他线路的非连接正交交叉继续使用拱桥；实体子线两端以无描边小尺寸实心 tap 表达连接。

## 5. 关键状态

| 状态 | 画布反馈 |
| --- | --- |
| 未选中母线 | 不显示子线起点，母线保持低干扰 |
| 已选中母线 hover | 显示一个空心 8px 候选点；母线长度/旋转控件保持现有行为 |
| 子线绘制中 | 显示普通电力接线预览；其他母线可显示目标候选，同一母线不显示目标 |
| 合法完成 | 两端 tap 联合滑移到稳定最优位置，显示普通电力子线和两个实心 tap |
| 重复或非法目标 | 不提交，不生成历史记录 |
| 删除子线 | 清理孤立 tap，并按剩余路径拆分或保留母线网络 |

## 6. 验收标准

- 用户能从已选中母线的空心候选点发起子线，并连接到另一条母线。
- 母线选择/拖动与子线发起可以稳定区分；按下母线本体不会误发起子线。
- 两端 tap 联合求优，平行母线在无障碍时得到垂直或水平直连，异向母线得到最短少折路径。
- 同一母线自连和完全重复的 tap 边被拒绝；不同位置的多条实体子线可保留。
- 删除唯一子线后两条母线拓扑断开；若仍有另一条路径则保持连通。
- JSON v6 往返、母线移动/旋转/缩短、普通交叉拱桥和现有图元—母线接线不退化。
- 视觉检查继续由用户完成；自动化覆盖拓扑合并/拆分、联合 tap 位置、DOM 状态、历史和构建。

## 7. 实施与非视觉验证结果

- `connectTerminals` 已支持两个不同母线终端：可新建纯母线子线网络、并入单侧既有网络、合并两侧网络，以及在同一网络中增加不同位置的实体子线。
- 同一母线自连在业务操作和项目导入校验中均被拒绝；现有节点对重复边约束继续阻止完全重复子线。
- 删除子线沿用网络归一化流程，孤立 tap 自动清理；唯一互联边删除后按同母线隐式邻接拆分网络，多路径场景保留连通。
- 路由器新增双母线候选集合联合搜索，两端 tap 同时参与路径长度、转折、滑移距离和稳定 offset 评分；水平/垂直母线均强制从垂直方向进入或离开。
- 画布已实现“选择母线后 hover 空心起点、点击发起、另一母线显示目标候选”的渐进交互；同一母线在接线状态下不显示目标。
- 后创建的多条子线会在当前已占用线路基础上联合重选两端 tap，避免同路径共线重叠。
- 全量 68 项单元/组件测试、主题一致性检查、TypeScript 类型检查和生产构建通过；3 条无截图 Playwright 流程通过，新增流程覆盖发起、完成、双端对齐、删除和撤销恢复。
- 构建仍保留既有 Three.js 大分块提示，浏览器流程仍出现既有 `THREE.Clock` 弃用警告；本次未引入新的失败项。
