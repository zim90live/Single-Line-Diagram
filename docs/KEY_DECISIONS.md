- 日期：2026-08-12
- 背景：用户要求 Codex 不主动通过 Computer Use 或截图方式进行视觉检查。
- 决策：除非用户明确要求，Codex 不主动使用 Computer Use、浏览器/Playwright 截图、图像查看工具或其他截图方式做视觉检查或视觉验收。视觉检查默认由用户完成，Codex可以执行非视觉自动化验证。

## KD-011：监控模式包含动画、图表和可替换的数据模拟源

- 状态：已接受
- 日期：2026-08-13
- 背景：用户明确后续监控模式需要动画、图表和数据模拟，技术架构不能只按低频图纸编辑设计。
- 决策：监控模式必须支持图上状态/流向动画、趋势或指标图表以及遥测数据模拟。模拟范围是温度、功率、压力、流量、开关状态和告警等运行数据生成，不包含电气潮流、暂态或冷却水力等物理计算。持久化的图纸业务文档与高频运行态数据分层管理；模拟数据和未来真实数据源通过统一接口接入，不把高频监控更新写入编辑历史或项目 JSON。
- 影响：第一阶段仍只实现编辑系统，但画布适配层、设备标识和扩展模型必须为运行态覆盖层留出边界。后续不需要为遥测模拟引入 C++/WASM 物理仿真内核；进入监控实现前，需确认动画规模和刷新频率，并据此完成 SVG/Canvas/WebGL 性能验证。

## KD-014：画布网格使用 8px 点阵呈现

- 状态：已取代
- 日期：2026-08-13
- 背景：用户要求把画布线网格改为点阵，降低连续网格线对图元内容的视觉干扰，同时保持现有 8px 几何约束。
- 决策：WebGL 网格以每 8px 世界单位一个基础点呈现，每 5 个基础单位使用更明显的主点帮助定位。滚轮缩放时不得使用固定屏幕点距或固定屏幕点径：基础点距、主点距和点径必须分别按 `8 × zoom`、`40 × zoom` 和各自世界半径同比例映射到屏幕；网格原点保持在世界坐标中。标尺必须共用同一个 8/40 世界单位序列，主刻度始终对应 40px 主点；缩小时可以省略过密的基础刻度并降低文字标签频率，但不得另建 16/80 等与点阵竞争的刻度序列。平移、缩放和高 DPI 下点阵必须与 8px 吸附网格保持一致；WebGL 不可用时也使用相同真实比例的点阵回退，不恢复线网格。
- 影响：缩放后的点阵、图元和标尺共享同一几何比例，不再出现主点与主刻度错位，或点距正确但点大小固定在屏幕上的错觉。该变化不改变图元位置、尺寸、JSON 数据和标尺数值；点对比度和常用缩放下的观感仍由用户完成视觉验收。
- 替代关系：被 KD-017 取代。保留 8px 最小世界单位和点阵形式，取消主次点及固定 8/40 可见序列。

## KD-017：网格采用 8px 倍数自适应单级点阵

- 状态：已接受
- 日期：2026-08-13
- 背景：固定显示 8px 基础点和 40px 主点时，缩放后的视觉密度和标尺层级仍难以保持一致。用户明确要求取消点的主次区别，并按缩放比例从 8、16、24px 等间隔中选择当前显示密度。
- 决策：业务几何与吸附的最小单位继续固定为 8px。所有可见网格点使用完全相同的屏幕半径、颜色和透明度，不再区分基础点与主点。当前可见世界间隔取“屏幕间距不小于 8px 的最小 8px 整数倍”：`zoom ≥ 1` 显示 8px，`0.5 ≤ zoom < 1` 显示 16px，`1/3 ≤ zoom < 0.5` 显示 24px，继续缩小时依次显示 32px、40px……标尺刻度直接使用同一个当前可见间隔；文字标签可以按可见点的整数倍降低密度，但不得脱离当前点阵序列。WebGL 与 CSS 回退必须使用相同规则和世界坐标原点。
- 影响：缩放只改变当前显示哪些 8px 网格点，不改变图元吸附、位置、尺寸、JSON 数据或标尺数值。状态栏显示当前可见间隔，便于用户确认比例尺。视觉密度和点阵观感仍由用户验收。
- 替代关系：取代 KD-014 的主次点、固定 8/40 可见序列和点径随 zoom 变化规则。

## KD-019：接线锚点定义在图元资产模板上

## KD-030：母线 tap 默认自动滑移并按完整端点方向优化路由

- 状态：已接受
- 日期：2026-08-14
- 背景：固定在用户点击位置的母线 tap 会产生不必要的水平折返；普通 A* 只统计主网格路径内部转折，未把图元锚点的默认向外出线方向纳入完整路径评分，导致等长路径在端点附近提前折弯。
- 决策：母线 tap 的持久化 offset 作为原始位置、稳定性偏好和求解失败回退值，实际绘制位置默认由路由器在所属母线的全部合法 8px 网格点中自动选择。候选路径先满足避障、正交、禁止共线和拱桥禁接入等硬约束，再依次最小化总长度、包含两端锚点过渡在内的总转折数和相对原始 offset 的滑移距离；最终使用固定方向与 offset 顺序确定性破同分。图元锚点的出线方向作为 A* 的初始和目标方向约束参与评分。
- 影响：不增加 Schema 字段、常驻 UI 或手动 tap 编辑；创建、图元/母线变换及载入后的派生重路由都会重新求解实际 tap。tap 拓扑身份和同母线隐式连通不变，保存/重载后由确定性规则恢复相同几何。详细规则见 `ROUTING_QUALITY_DESIGN_BRIEF.md`。
- 补充：母线接入位置的占用按母线法向两侧分别计算。已有接线只阻止同一位置的同侧出线，位于相反侧的新接线可共享同一派生 offset；真正穿过母线的非连接交叉仍同时封锁两侧。该规则同时用于图元—母线接线和双母线子线，不新增持久化侧向字段。

- 日期：2026-08-14
- 背景：以最外侧已有 tap 作为母线缩短下限，会让接入线路较多的母线无法继续收紧；用户要求长度手柄能够越过旧连接位置，并让连接点随母线尺寸一起压缩。
- 决策：母线连接点数按不同 `busbar-tap` 拓扑节点计算，同一 tap 即使连接多条普通边仍只计一个。母线动态最短长度为 `max((tap 数 - 1) × 8px, 8px)`。缩短时以本次手势开始时的母线长度和持久化 offset 为基准按比例投影全部 tap，再吸附到 8px 网格；投影发生碰撞时保持原有顺序，并为相邻 tap 保留至少 8px 间距。拖回手势起始长度可恢复原 offset；扩长已提交的母线不主动把压缩后的 tap 反向拉开。tap ID、连接边和拓扑关系保持不变，派生路由按新几何重新求解。
- 影响：基础母线最短长度由 40px 降为 8px，项目 Schema 继续保持 v5。母线几何与受影响 tap offset 在同一历史事务中预览和提交，撤销/重做必须同时恢复；导入校验继续通过 tap 范围、8px 网格和同位置唯一性保证文档满足动态容量约束。
- 替代关系：取代 KD-029 及 KD-031 承接的“缩短不得越过已有 tap”和固定 40px 下限；不改变 KD-030 的 tap 自动滑移、KD-031 的母线子线互联及其他母线拓扑规则。

## KD-033：编辑器采用统一的取消、保存和 Duplicate 快捷键

- 日期：2026-08-14

## KD-034：颜色拖拽采用原位预览与单次业务提交

- 日期：2026-08-14

- 决策：可配置颜色图元在颜色选择器连续 `input` 期间只更新属性面板本地草稿，并通过画布命令原位修改当前图元 SVG 的 `feFlood` 与颜色数据属性；不得写入项目文档、dirty 状态、撤销历史或触发线路重路由。浏览器发出最终 `change`，或控件失焦且存在未提交颜色时，才把规范化后的六位十六进制颜色提交一次。恢复默认仍立即提交一次；切换选择或卸载控件时清理未提交预览。
- 影响：颜色拖拽的高频路径从“整份项目与路由更新”收敛为固定数量 DOM 属性更新，最终颜色继续使用既有实例属性、JSON、IndexedDB 和单事务撤销/重做语义。该优化不改变 Schema、图元可配置范围或 SVG 源文件。

## KD-035：同锚点多线采用端点逻辑边与派生共享路径

- 状态：已接受
- 日期：2026-08-14
- 背景：固定在线路坐标上的显式分叉一旦创建就不会随设备布局自动迁移，用户难以调整线路；同时“一个图元锚点只能连接一条边”迫使用户通过子线候选点建立分叉，增加操作负担。
- 决策：同一图元锚点在一个连通网络中只保存一个稳定节点，但节点度数允许为一到多条逻辑边；使用已接线锚点再次连接时复用该节点，连接另一个兼容网络时合并网络。普通线路不再是接线起点或终点，业务节点只包含图元锚点和母线 tap；边只记录端点关系。线路几何按网络联合派生：同一网络的后续逻辑边允许低成本复用已生成网格段并自动形成共同路径，其他网络与母线仍作为共线障碍；图元变化、增删连接或载入时重新计算。派生分叉不写入 JSON、不绘制连接点，也不可选择、拖动或接线。点击独立支路选择逻辑边，点击多条逻辑边共用的主干选择整个网络；删除后按剩余端点关系重新路由。不同网络正交交叉仍使用拱桥表达不连通。

- 替代关系：取代 KD-027 的固定分叉与单锚点单边规则，以及 KD-028 的线路分叉入口；其余仍有效原则由本决策承接。

## KD-036：高频拖动采用逐帧合并与两阶段线路预览

- 状态：已接受
- 日期：2026-08-14
- 背景：同锚点多线改造后，图元每个 `pointermove` 都会触发整个共享网络重新寻路；共享段的零代价又使交互寻路关闭有效启发式并退化为大范围 Dijkstra 搜索，导致图元拖动和起线跟随明显卡顿。
- 决策：图元预览、起线指针和状态栏坐标的高频更新统一在浏览器动画帧内只提交最新值，重复落在同一 8px 网格点的起线事件不触发更新。图元移动、缩放和旋转期间只派生轻量线路几何：端点保持附着、两端同位移时整体平移、未受影响的共同主干保持稳定；手势提交后再执行一次完整避障与共享路径重路由。起线过程允许复用所属网络路径，但交互预览使用完整 A* 启发式优先保证帧延迟；连接完成后的正式网络路由仍使用共享段偏好重新求解最终几何。
- 影响：高频交互不再与整网寻路次数线性绑定，最终落库线路仍遵守 8px 正交、图元避障、网络内共享、网络间共线禁止和非连接拱桥规则。轻量拖动预览是瞬时派生状态，不进入 Schema、JSON、IndexedDB 或撤销历史，也不恢复固定或可见分叉点。
- 补充：方向键连续移动复用同一两阶段机制。每个方向键事件继续累计对应方向的 8px 位移，但坐标与关联线路只按动画帧显示最新轻量预览；松键后 120ms 内无新方向键，或画布失焦、开始鼠标操作、执行其他快捷键时，将整段移动一次性提交并执行一次正式重路由。整段连续移动只占一个撤销步骤。

## KD-040：对象复制包含选区内部逻辑接线关系

- 状态：已接受
- 日期：2026-08-17
- 背景：多选一组已经接线的设备或母线后，若只复制对象而丢失它们之间的线路，用户仍需手工重建整组拓扑，无法高效复用重复单元。
- 决策：`Command/Ctrl+C`、`Command/Ctrl+V` 和 `Command/Ctrl+D` 将当前选择视为对象集合，并复制由该集合诱导的内部线路子图。一个逻辑边仅在其两个端点所属图元或母线都被选择时复制；连向选区外对象的边、孤立节点和 tap 不复制。复制母线内部关系时生成新的 `busbar-tap`；复制图元关系时保留资产锚点引用。所有新图元、母线、tap、节点、边和网络均获得新 ID，网络类型根据复制后的实际端点重新解析，线路共享段、分叉位置、折点和拱桥继续由新对象位置自动路由，不复制旧路径坐标。独立选择普通线路后复制仍不支持。
- 影响：对象及内部拓扑作为同一个历史事务提交和撤销。无内部线路的对象继续保持 16px 对角偏移；包含内部线路时，为避免副本与原对象重叠造成路由无解，系统沿选区较短轴移出原包围框并保留 16px 间隔，连续粘贴沿同一向量递增。裁掉选区外支路后可能产生多个内部连通分量，系统会将其规范化为独立网络。项目 Schema、JSON 和 IndexedDB 格式保持 v6 不变。
- 替代关系：部分取代 KD-027、KD-033 和 KD-039 中线路拓扑不随复制操作生成的边界；保留业务拓扑只保存端点逻辑边、派生路径不持久化以及选区外线路不复制的原则。

## KD-041：非连接交叉采用真圆弧与局部底衬

- 状态：已接受
- 日期：2026-08-17
- 背景：现有拱桥使用二次贝塞尔曲线，8px 网格下控制点虽偏移 4px，但实际顶点只抬高约 2px，在线宽 1.5px 和深色点阵上难以辨认为非连接跨越；后续监控流动还需要沿同一显示路径经过拱桥。
- 决策：不同网络的非连接交叉继续由后生成线路跨越，但显示几何改为 SVG 真圆弧。孤立交叉默认占用 8px 路径跨度并抬高 4px；靠近线段端部或密集相邻交叉时按可用距离收紧，禁止反向或互相覆盖。每条含拱桥线路额外使用一条合并全部局部圆弧的画布色底衬路径，底衬保持 12px 屏幕线宽；彩色线路保持既有 1.5px 非缩放描边。可见线和透明命中线必须使用同一带拱桥路径。禁止使用滤镜、阴影、Mask 或为每个交叉生成独立 DOM 节点。
- 影响：每条含拱桥线路最多增加一个静态 SVG 底衬 path，路径字符串按路由边、交叉集合和网格尺寸缓存；没有交叉的线路不增加 DOM。拱桥继续是纯派生显示几何，不进入 Schema、JSON、IndexedDB、连接选择或拓扑分析。
- 替代关系：细化 KD-028 与 KD-035 保留的非连接拱桥视觉规则，不改变不同网络可正交交叉、默认不连通及共线重叠禁止的规则。
- 补充：根据 2026-08-17 用户视觉反馈，默认圆弧由初版 16×8px 收敛为 12×6px，画布色底衬由 5px 加粗为 7px；只调整显示参数，不改变拓扑与性能边界。
- 补充：根据后续视觉对比，默认圆弧继续由 12×6px 收敛为 8×4px，画布色底衬由 7px 加粗为 12px；其他显示、拓扑与性能边界保持不变。

## KD-042：监控流动采用 WebGL 批量覆盖并复用显示路径

- 状态：已接受
- 日期：2026-08-17
- 背景：后续监控模式需要在包含拱桥和共享路径的一次图上表达电流与冷却水流向；若为每条线路或每个粒子持续修改 SVG `stroke-dashoffset`、路径数据或 React 状态，规模增长后会产生大量主线程绘制和组件更新。
- 决策：编辑/静态线路继续由 SVG 表达，电流与水流动画使用独立 Three.js / React Three Fiber WebGL 运行态覆盖层。路由结果与交叉元数据生成一份可缓存的显示路径，SVG 编译为直线与真圆弧 path，WebGL 编译为相同路径的采样/弧长数据，保证流动经过拱桥而不会在交叉处产生错误连通暗示。动画按线路类型、方向和样式批量或实例化绘制；每帧只更新统一时间参数或 GPU Buffer，遥测值以较低频率更新速度、方向、密度和强度并在 GPU 侧平滑。运行态不得写入项目 JSON、编辑历史或触发业务路由。

- 补充关系：扩展 KD-011 与 KD-012 的监控运行态/WebGL 分层，不改变 SVG 负责图元和编辑交互、WebGL 负责网格与高频运行态的既有边界。

## KD-043：正式线路路由采用 Worker 派生快照与 latest-wins 调度

- 状态：已接受
- 日期：2026-08-17
- 背景：真实电力归档包含 67 个图元、13 条母线和 73 条逻辑边。完整网络 A* 约需 300ms，原实现又在 React render 和接线完成事件中同步执行，导致已接线图元松手出现约 692ms 主线程长任务；起线预览还会重复建立图元、障碍和占用索引。
- 决策：正式线路几何继续作为不持久化的派生数据，但由独立 Web Worker 计算。主线程只保留一个活动任务和一个可替换的最新待处理任务；旧结果不得覆盖新文档状态。图元/母线交互期间继续显示上一份稳定快照的轻量端点附着预览，提交后保持该预览直到新快照到达；新建逻辑边先使用已验证的接线预览作为临时显示路径，避免等待 Worker 时闪烁或消失。Worker 结果以 React transition 应用；不支持 Worker 或 Worker 启动失败时才使用延迟主线程兼容降级。接线会话缓存端点、障碍、线路占用和网格阻挡边，指针预览使用有状态数上限的交互搜索；正式 Worker 路由仍执行完整确定性搜索。画布中的图元和线路边按稳定对象/路径属性记忆渲染，应用级回调保持稳定，开发入口不再使用会让大型画布交互重复执行的 StrictMode 包装。
- 影响：完整 A* 不再占用受支持浏览器的交互主线程；拖动、方向键移动、母线变换和接线提交不必等待正式路由。路由 Worker 会产生独立构建产物并复制当前图纸输入，旧快照与临时路径只存在于内存，不进入 Schema、JSON、IndexedDB 或撤销历史。若未来单图规模显著超过当前真实归档，应继续评估 Worker 内部空间索引、增量网络重路由和结果传输成本，而不是把正式 A* 移回 React render。
- 补充关系：扩展 KD-036 与 KD-038 的两阶段交互预览；不改变 KD-035 的网络共享、KD-041 的拱桥显示及线路拓扑持久化边界。
- 补充：交互预览的状态数上限不得形成固定可接线距离。长距离预览采用轻度加权 A*，优先朝终点扩展，避免在大量等价最短状态中耗尽预算；该权重只影响虚线预览和新边临时路径，Worker 最终路由继续使用权重 1 的完整确定性评分。

## KD-044：母线与逻辑子线颜色作为业务属性持久化

- 状态：已接受
- 日期：2026-08-17
- 背景：图元实例已经支持颜色编辑，但母线和普通子线仍只能使用线路类型默认色；系统原有原生颜色输入也无法稳定控制不同操作系统颜色面板默认显示 HEX 模式。
- 决策：Schema 升级至 v7，在 `Busbar.color` 与 `ConnectionEdge.color` 保存可选的标准六位十六进制颜色；未设置时继续使用既有电力或冷却类型默认色。属性面板统一使用明确显示 `HEX` 的可编辑文本值作为默认颜色交互，并保留色块入口打开系统颜色面板。连续输入只通过 SVG CSS 自定义属性原位预览，确认后单次写入项目与撤销历史；恢复默认删除可选颜色字段。独立支路选择只修改对应逻辑边，共享主干的网络选择批量修改该网络全部逻辑边；一条或多条纯母线选择可批量改色。
- 影响：v1–v6 项目载入时无损迁移至 v7；颜色进入 JSON、IndexedDB、撤销/重做及对象内部拓扑复制，但不进入派生路径、A* 评分或 Worker 路由几何。线路类型仍决定未自定义时的默认颜色，自定义颜色不改变拓扑类型、兼容性或监控数据语义。
- 补充关系：扩展 KD-026 的图元颜色编辑策略，并保持 KD-035、KD-041 与 KD-043 的拓扑、拱桥和异步派生路由边界。
- 替代关系：其中“色块入口打开系统颜色面板”的交互被 KD-046 取代；颜色字段和持久化边界继续有效。

## KD-045：图元设备标识采用自动侧向标签与单选后二阶段交互

- 状态：已接受
- 日期：2026-08-17
- 背景：运维图纸需要始终辨识每个设备，但把名称、背景或卡片重新包入 SVG 图元会污染既有尺寸、框选、吸附和线路路由；标签若始终可直接操作，又会与图元选择和密集画布交互冲突。
- 决策：每个普通图元始终在旁侧显示 `properties.tag` 设备标识，标签为无背景的水平世界空间文字，随画布缩放但不参与图元几何、框选、吸附、变换包围框或线路障碍。系统默认在画布坐标的下、右、上、左四侧自动评分，硬避让本图元锚点及其初始出线走廊，并软避让其他图元与已排布标签。只有恰好单选一个普通图元时，其标签才进入可点击和拖动的二阶段交互；拖动只确定 `top | right | bottom | left` 侧向，具体沿边位置由系统使用独立于主画布 8px 网格的 2px 精细步进避让。多选不允许标签交互，不增加双击或原位编辑，设备标识内容继续在右侧属性面板修改。旋转图元不旋转标签，也不改变标签的画布侧向。
- 影响：Schema 升级至 v8，`DiagramElement.labelPlacement` 可选保存人工侧向，缺省代表自动；v1–v7 项目载入时为缺失设备标识的图元生成默认值。标签侧向进入撤销/重做、JSON、IndexedDB 和图元复制，派生文字坐标不持久化。重复设备标识暂不阻止保存，只在属性面板提示。详细约束见 `ELEMENT_LABEL_DESIGN_BRIEF.md`。
- 替代关系：部分取代 KD-014 中“画布不附加名称”的显示边界；仍保留 SVG 本体不增加背景、卡片和任意尺寸外壳的约束。
- 补充：根据 2026-08-17 用户视觉反馈，标签与图元边界的默认视觉间距先由 8px 收紧为 4px，世界字号由 12px 收紧为 10px 并同步文字宽度估算。
- 补充：根据后续视觉反馈，默认视觉间距继续由 4px 收紧为 2px，并以独立的 2px 精细避让步进取代沿边 8px 位移步进；图元、锚点、母线和接线的 8px 网格规则不变。

## KD-046：颜色编辑使用应用内 HEX 选择器且母线 tap 继承母线颜色

- 状态：已接受
- 日期：2026-08-17
- 背景：浏览器原生 `input[type="color"]` 的颜色面板由操作系统控制，无法可靠指定默认显示 HEX，且在面板关闭与失焦时存在提交时机差异。共享主干包含不同颜色逻辑边时，显示第一条边的默认色还会误导用户；母线改色后 tap 保持电力默认色也破坏了连接归属表达。
- 决策：色块入口不再调用系统颜色面板，而是在属性面板内展开自有颜色选择器，只提供饱和度/亮度、色相和明确的 HEX 输入，并以“完成/取消”作为预览事务边界。独立逻辑边重新选择时始终从持久化 `ConnectionEdge.color` 回显；网络选择包含多种颜色时输入显示“多种颜色”，用户选定新值后才统一覆盖网络边。已建立 `busbar-tap` 与当前候选 tap 的显示颜色始终继承所属 `Busbar.color`，未自定义时回退电力默认色；预览、提交、恢复默认、撤销和重做均同步。
- 影响：颜色选择不再受 macOS、Windows 或浏览器 RGB/HEX 面板差异影响；连续调整继续只做 SVG 原位预览，完成后单次进入历史。tap 继承只改变派生显示，不新增 Schema 字段，也不改变线路边颜色、拓扑或路由。
- 替代关系：部分取代 KD-044 的系统颜色面板入口；保留其 Schema v7 颜色字段、网络批量编辑和持久化决策。

## KD-047：空选属性面板按类别提供画布颜色全局替换

- 状态：已接受
- 日期：2026-08-17
- 背景：逐个选择图元、母线或子线改色不适合统一整张图的表达；用户需要在没有对象选择时看到当前画布的实际颜色构成，并从颜色本身发起批量调整。
- 决策：主画布未选择图元、母线或子线时，右侧属性面板按图元、母线、子线三个固定类别汇总当前实际颜色，每种颜色只显示一次并标注使用对象数。点击某个颜色后复用 KD-046 的应用内 HEX 选择器，只预览和替换当前画布内同类别、且修改前实际颜色等于该颜色的对象。默认色和显式自定义色按最终显示值合并统计；不支持实例改色的原始 SVG 图元不进入图元颜色组。完成替换后统一写入显式颜色属性并作为一个历史事务提交，取消则恢复全部预览。

- 补充关系：扩展 KD-026、KD-044 与 KD-046 的颜色编辑入口和批量范围，不改变单对象、网络选择及恢复默认的原有行为。

## KD-048：子线与母线共享追加选择和批量颜色事务

- 补充关系：扩展 KD-035 的线路选择、KD-037 的母线混合选择，以及 KD-044、KD-046 的批量颜色与预览事务；不开放普通图元与线路的混合改色，也不增加线路复制能力。
