# 监控模式电流与水流动画设计约束

最后更新：2026-08-18
状态：电力流向首轮已实现，冷却方向与遥测适配待后续

## 1. 目标与边界

监控模式需要在既有电力、一次回路冷/热和二次回路冷/热网络上表达流向、速度、强度和无流量状态。动画必须复用编辑模式产生的稳定拓扑与显示路径，包括共享主干、自动分叉和非连接交叉拱桥，但不得修改编辑文档。

当前已实现编辑/监控 Tab、监控只读画布、编辑属性面板与监控画布共享的 Switch 独立运行态、Grid 到 POD 的有效电力业务路径裁剪和 WebGL 移动虚线覆盖。遥测模拟器、趋势图表、真实数据适配、冷却 Source/Target 与规模化性能降级仍属于后续增量。

## 2. 首轮运行规则

- 监控模式不允许新增、选择或修改图元、母线、子线和标签；保留层级导航、滚轮缩放及中键平移。
- Switch 缺省 Off。监控画布点击或编辑模式属性面板开关均切换 On/Off SVG，并把状态立即写入独立 `monitorSwitchStates` IndexedDB 表；运行态不修改项目 JSON、dirty 状态或撤销历史。关/开显示颜色分别由项目实例属性配置，属于低频图纸配置而非遥测状态。
- 电力 Source 为 `Grid`，Target 为算力 POD 与动力 POD。拓扑传播连接普通子线、非 Switch 图元内部锚点和母线相邻 tap；Target 终止内部传播。
- 移动虚线表达实际业务流动，不表达单纯带电。系统从所有可达 Target 沿 Grid 多源最短距离反向追踪，取全部等长最短 Source→Target 路径的并集；无 Target 的整条链路和有效主干旁的死端分支均不动画。母线只动画并集涉及的相邻 tap 区间。
- Off Switch 断开自身不同锚点之间的传播，并隐藏所有直接以该 Switch 锚点为端点的普通子线动画；On 只恢复路径资格，只有重新形成有效 Source→Target 路径时才恢复动画。线路方向不使用接线创建顺序。
- 首轮没有冷却设备 Source/Target 定义，因此冷却网络不动画；业务角色明确后复用相同运行拓扑接口。

## 3. 分层方案

```text
项目业务层：ConnectionNetwork、节点、逻辑边、设备绑定
派生几何层：正交路由、共享路径、交叉元数据、真圆弧显示路径
SVG 静态层：图元、静态线路、拱桥、选择与编辑命中
WebGL 运行态层：电流/水流粒子、流动短线、方向与强度动画
遥测适配层：模拟源 / 真实数据源 → 统一运行态快照
```

- SVG 静态层保持线路轮廓和编辑交互，不承担高频动画。
- WebGL 层与 SVG 使用同一世界坐标和视口变换，覆盖在静态线路上方但位于编辑手柄下方。
- 业务拓扑不保存折点、拱桥或动画粒子；它们全部是可重建的派生状态。

## 4. 显示路径复用

- 路由完成后以 `edgeId + routeRevision + crossingRevision` 为缓存边界生成显示几何。
- 显示几何保留有序直线段和真圆弧段。SVG 编译为 path 字符串；WebGL 编译为采样点、累计弧长或等价 GPU Buffer。
- 动画必须沿真圆弧跨过其他网络，不能沿原始直线穿过交叉点，避免产生错误连通暗示。
- 图元、母线、tap、网络或交叉关系变化时重建受影响路径；遥测数值变化和每个动画帧不得重算路由或 path。

## 5. 动画批处理

- 按线路类型、方向和视觉样式分批，使用 Instancing、合并 Buffer 或等价批量方案；不得为每个粒子创建 React/SVG 节点。
- 每帧只更新时间 Uniform、批次相位或必要的 GPU Buffer。速度、方向、密度、颜色强度等运行态以较低频率写入缓冲，并由 GPU 在帧间平滑。
- React 只处理模式、选择、配置和低频摘要；不得把粒子位置或逐帧相位放入 React State。
- 不把 SVG `stroke-dashoffset` 作为规模化最终方案；仅可在明确的小规模原型中经基准验证后临时使用。
- 首轮把活动普通子线、拱桥采样段与母线导通区间合并成单个 BufferGeometry；相同方向、相同宽度的共享段只上传一次。普通子线使用屏幕空间 2px 三角带覆盖 1.5px SVG 静态线，母线使用 4.5px 三角带覆盖 4px 静态线；相邻采样段端部搭接以消除直角和拱桥处的露色缝隙。Shader 使用 `#303238`、0.92 透明度的中性深灰 6px 实段加 6px 间隔，并以统一时间 Uniform 沿业务方向移动。

## 6. 运行与降级策略

- 只动画视口内可见线路；视口外批次跳过或降低更新频率。
- 当前实现与静态 SVG 共用视口加 160px 屏幕 overscan 的可见线路集合，平移后才重建进入缓冲区的派生路径；开启系统“减少动态效果”时 WebGL 改为按需帧并把移动相位冻结，不再持续请求动画帧。
- 页面隐藏、离开监控模式、网络无流量或数据过期时暂停对应动画。
- 支持 `prefers-reduced-motion`：以静态方向标识、亮度或低频脉冲替代连续位移。
- 当帧时间超出目标时，按粒子密度、采样精度、更新频率、非关键动画的顺序降级，不降低告警和关键状态可见性。
- 编辑模式默认不运行动画，避免与拖动、起线和自动路由竞争主线程/GPU 预算。

## 7. 数据更新边界

- 模拟源和真实数据源统一输出设备/网络运行态快照，包括时间戳、方向、归一化强度、速度、有效性和告警状态。
- 高频遥测不写项目 JSON、IndexedDB 或编辑历史；Switch 等需要跨刷新恢复的低频操作状态可以写入独立运行态表，但不得改变项目 dirty 状态。
- 数据刷新与视觉帧率解耦。遥测可按业务频率更新，渲染层使用时间戳进行平滑或保持，不要求数据源以 60Hz 推送。

## 8. 后续性能基线

进入规模化遥测、图表和多类型并行动画前必须由用户确认或通过样例测得：

- 单张图纸典型与最大图元、母线、逻辑边和派生网格段数量。
- 同时有流量、告警和状态动画的线路数量。
- 模拟与真实遥测刷新频率、允许的数据延迟和图表时间窗口。
- 目标浏览器、屏幕分辨率、设备 GPU/CPU 档位和后台运行要求。

随后建立至少包含帧时间、主线程长任务、React 提交次数、绘制批次数、GPU/内存占用和视口裁剪收益的基准。性能目标不得在缺少规模数据时凭经验写死。

## 9. 验收原则

- 动画沿线路和拱桥连续运行，不在非连接交叉处跳网或误入另一网络。
- Off Switch 两侧的直接相邻线路均不显示动画，On 后按业务拓扑恢复。
- 闭合 Switch 但链路没有算力 POD 或动力 POD 时整链不动画；有效主干旁没有 Target 的死端支路也不动画；两条等长有效路径均保留。
- 遥测更新不会增加编辑历史、dirty 状态或触发线路重路由。
- 典型规模下交互与动画保持稳定；超出预算时按既定策略平滑降级。
- 隐藏页、无流量网络和减少动态效果模式正确暂停或替代表达。
- 视觉质感、速度感和不同线路类型的辨识度由用户完成验收。
