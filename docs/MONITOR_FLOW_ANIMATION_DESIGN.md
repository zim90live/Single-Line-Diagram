# 监控模式电流与水流动画设计约束

最后更新：2026-09-02
状态：电力、冷却动画、无流动深色状态与制冷视觉流量控制均已实现；待用户视觉与真实图纸操作验收

## 1. 目标与边界

监控模式需要在既有电力、一次回路冷/热和二次回路冷/热网络上表达流向、速度、强度和无流量状态。动画必须复用编辑模式产生的稳定拓扑与显示路径，包括共享主干、自动分叉和非连接交叉拱桥，但不得修改编辑文档。

当前已实现编辑/监控 Tab、监控只读画布、Switch 独立运行态、电力 Source 到 Target 的有效业务路径裁剪，以及制冷水泵闭环和显式管路源头开放流路求解。电力与制冷共享 WebGL 移动虚线骨架但使用独立样式入口；制冷由确定性模拟 Provider 驱动并执行子线单向约束和阀门门控，不复用电力最短路径。趋势图表、真实数据适配与规模化性能降级仍属于后续增量；制冷详细边界见 `COOLING_PIPELINE_DIRECTION_DESIGN_BRIEF.md`。

## 2. 首轮运行规则

- 监控模式不允许新增、移动、旋转、缩放、接线、删除或修改图纸结构；保留层级导航、滚轮缩放及中键平移。可单选水泵、阀门和 On/Off 图元，并在右侧运行属性面板控制会话工况或已有 On/Off 状态。
- Switch、2WV、CV 缺省 Off。监控画布点击或编辑模式属性面板开关均切换 On/Off SVG；状态作为 Schema v23 图元快照进入本地项目与 JSON 导入导出，同时立即镜像到兼容 `monitorSwitchStates` IndexedDB 表。切换不修改项目 dirty、更新时间或撤销历史。关/开显示颜色分别由项目实例属性配置，属于低频图纸配置而非遥测状态。
- 制冷拓扑中 2WV 作为普通阀门，On 时按同回路双向连通；CV 作为 Schema v24 的 `check-valve` 止回阀，On 时只允许入口→出口，Off 时完全阻断。该内部方向与相邻子线的 `flowDirection` 同时生效，任一约束冲突都保持静态。
- 电力 Source 为 `Grid`、`Generator` 与 `Battery`，Target 为算力 POD、动力 POD 与 `FM`。拓扑传播连接普通子线、非 Switch 图元内部锚点和母线相邻 tap；Target 终止内部传播。
- 设备子图只有在父图关联设备真实带电时才获得外部供电。电力子图可把逻辑子线的物理起点端或终点端显式标记为外部供电入口；只要至少存在一个显式入口，全部入口端合并为一个上游边界并取代母线端点、单向自由边界的自动 Source 推断，电流必须先经过真实进线。入口配置不自动修改子线通行方向，冲突时停流；没有显式入口的历史图纸继续使用原自动回退。
- 显式入口供电的子图中，若自动方向母线至少一个 tap 已进入有效供电路径，则动画补齐该母线全部相邻 tap 区间及两端物理尾段；路径外区间按距显式入口的拓扑距离向外传播，冲突区间仍停流。已带电设备连接到该母线的其他明确单向入线也同时动画，避免双路输入因 tap 距离差只保留较短一路；双向线、Battery-group 和普通冗余环路不据此扩展。
- `cabinet-device` 表示计算机柜并始终作为电路终点；它的多个锚点是彼此独立的 A/B 进线终端，拓扑不得通过机柜内部从一个锚点传播到另一个锚点。两路都可达时分别回溯并同时动画，只有一路可达时机柜仍带电但另一进线保持静态，两路均不可达时停电。
- 移动虚线表达实际业务流动，不表达单纯带电。系统按每个 Source 图元独立计算到所有可达 Target 的最短距离并反向追踪，再取各 Source 全部等长最短路径的并集；邻近 Battery 或 Generator 不得抢占并隐藏 Grid 的较长有效路径。无 Target 的整条链路和有效主干旁的死端分支均不动画，母线只动画并集涉及的相邻 tap 区间。同一普通子线或母线区间若被不同 Source 推导为相反方向，本轮不动画该冲突区间，等待真实运行态或潮流方向消歧。上述无流动区间统一在原业务色上叠加 50% 黑色，保留色相但降低明度。
- Off Switch 断开自身不同锚点之间的传播，并隐藏所有直接以该 Switch 锚点为端点的普通子线动画；On 只恢复路径资格，只有重新形成有效 Source→Target 路径时才恢复动画。线路方向不使用接线创建顺序。
- 冷却网络以运行水泵出口为闭环注入点、同一水泵入口为回收点，也允许在编辑模式把冷却子线的物理起点端或终点端配置为“水流源头”。每个显式源头按固定 `100 m³/h` 基准流向同一管网中其他可达、连接度为 1 的开放自由端；多个出口按等阻力分流，并可与水泵贡献线性叠加。两类驱动均执行网络类型、子线允许方向、普通阀门和 CV 入口→出口门控；端口角色缺失、泵开路、停泵、零功率、源头无可达出口、关阀或逆单向约束时不产生对应流量，不猜测压力或工程水力。监控视觉保留双层管体，主要/辅助内芯分别使用 `2px / 1px` 世界空间宽度，并叠加与电路一致的深色 `6px / 6px` 移动虚线，不制作流光、液滴或粒子效果。监控画布点击泵阀只选择设备，右侧运行属性面板负责控制状态和水泵功率。
- 当前 Grid、Generator、Battery 实例只要属于已识别 Source 且拓扑可达就参与计算，尚未根据 Generator 运行/停机或 Battery 充电/放电状态门控；该运行态接入作为后续增量单独实现。

## 3. 分层方案

```text
项目业务层：ConnectionNetwork、节点、逻辑边、设备绑定
派生几何层：正交路由、共享路径、交叉元数据、真圆弧显示路径
SVG 静态层：图元、静态线路、拱桥、选择与编辑命中
WebGL 运行态层：电流/水流粒子、流动短线、方向与强度动画
遥测适配层：模拟源 / 真实数据源 → 统一运行态快照
```

- SVG 静态层保持线路轮廓和编辑交互；监控模式按流动资格把最终显示几何拆为业务原色与压暗色区间，直接绘制最终不透明内芯，但不反写项目中的线路业务色。
- WebGL 层与 SVG 使用同一世界坐标和命令式视口引用，覆盖在静态线路上方但位于编辑手柄下方，只绘制有流动区间的移动虚线。无流动暗色在 CPU 侧按原色与黑色各 50% 预混后由 SVG 直接绘制，禁止先保留完整原色内芯再叠加静态覆盖，以免抗锯齿边缘透出底色。中键平移逐帧更新该引用、SVG 合成变换和 WebGL Uniform，不依赖 React 为每帧传递新视口属性。
- 业务拓扑不保存折点、拱桥或动画粒子；它们全部是可重建的派生状态。

## 4. 显示路径复用

- 路由完成后以 `edgeId + routeRevision + crossingRevision` 为缓存边界生成显示几何。
- 显示几何保留有序直线段和真圆弧段。SVG 编译为 path 字符串；WebGL 编译为采样点、累计弧长或等价 GPU Buffer。制冷还必须复用其普通 `8px` 圆角弯头、短段收紧、分叉直角和 `16 × 8px` 拱桥后的最终显示几何，不能退回未经圆角处理的正交路由点。
- 动画必须沿真圆弧跨过其他网络，不能沿原始直线穿过交叉点，避免产生错误连通暗示。
- 图元、母线、tap、网络或交叉关系变化时重建受影响路径；遥测数值变化和每个动画帧不得重算路由或 path。

## 5. 动画批处理

- 按线路类型、方向和视觉样式分批，使用 Instancing、合并 Buffer 或等价批量方案；不得为每个粒子创建 React/SVG 节点。
- 每帧只更新时间 Uniform、批次相位或必要的 GPU Buffer。速度、方向、密度、颜色强度等运行态以较低频率写入缓冲，并由 GPU 在帧间平滑。
- React 只处理模式、选择、配置和低频摘要；不得把粒子位置或逐帧相位放入 React State。
- 不把 SVG `stroke-dashoffset` 作为规模化最终方案；仅可在明确的小规模原型中经基准验证后临时使用。
- 首轮按 `power` / `cooling` 样式把活动子线、拱桥采样段与母线导通区间分别合并为 BufferGeometry；相同方向、相同宽度和相同速度的共享段只上传一次。电力普通子线使用固定屏幕空间 `2px` 三角带覆盖静态线，电力母线使用固定屏幕空间 `4.5px` 三角带；相邻采样段端部搭接以消除直角和拱桥处的露色缝隙。当前 Shader 使用 `#303238`、0.5 透明度的中性深灰 6px 实段加 6px 间隔，并以统一时间 Uniform 沿业务方向移动。
- 制冷首版复用上述深色 `6px / 6px` 移动虚线运动语言和 WebGL 批处理能力，但线宽使用与静态角色内芯一致的世界空间宽度（主要 `2px`、辅助 `1px`），Shader 根据 zoom 换算屏幕覆盖宽度；移动虚线和 SVG 无流动静态内芯在全部缩放级别都必须保持同宽。物理区间模拟流量的符号决定方向、绝对值缩放移动速度。制冷使用独立样式入口，即使其他参数与电路同值，后续调整制冷视觉也不得连带改变电路。该复用不包含电力 Source→Target 最短路径算法。
- 监控模式先从最终可见线路几何中按共线区间扣除全部有效流动段，再把流动区间与余下静止区间分别编译为原色和最终暗色 SVG 子路径；原完整内芯在监控模式隐藏。扣除按物理区间执行，可处理一条逻辑边只有中间或端部流动、共享段反向引用以及母线相邻 tap 的局部流动；静态共享段不因重复逻辑边多次绘制。

## 6. 运行与降级策略

- 只动画视口内可见线路；视口外批次跳过或降低更新频率。
- 当前实现与静态 SVG 共用视口加 160px 屏幕 overscan 的可见线路集合。中键平移每帧只移动已有集合，累计 120px 屏幕位移或手势结束时才同步 React 并重建进入缓冲区的派生路径；开启系统“减少动态效果”时 WebGL 改为按需帧、冻结移动相位，并由命令式视口更新显式请求单帧重绘。
- 页面隐藏、离开监控模式、网络无流量或数据过期时暂停对应动画；没有任何移动虚线、只有 SVG 静态无流动线路时，不挂载 WebGL 动画层。
- 支持 `prefers-reduced-motion`：以静态方向标识、亮度或低频脉冲替代连续位移。
- 当帧时间超出目标时，按粒子密度、采样精度、更新频率、非关键动画的顺序降级，不降低告警和关键状态可见性。
- 编辑模式默认不运行动画，避免与拖动、起线和自动路由竞争主线程/GPU 预算。

## 7. 数据更新边界

- 模拟源和真实数据源统一输出设备/网络运行态快照，包括时间戳、方向、归一化强度、速度、有效性和告警状态。
- 高频遥测不写项目 JSON、IndexedDB 或编辑历史。Switch、2WV、CV 这类需要存档和跨刷新恢复的低频操作状态属于例外：写入 Schema v23 图元快照并镜像到独立运行态表，但不得改变项目 dirty、更新时间或撤销历史；水泵与其他非双状态阀门的会话模拟状态仍不持久化。
- 数据刷新与视觉帧率解耦。遥测可按业务频率更新，渲染层使用时间戳进行平滑或保持，不要求数据源以 60Hz 推送。

## 8. 后续性能基线

进入规模化遥测、图表和多类型并行动画前必须由用户确认或通过样例测得：

- 单张图纸典型与最大图元、母线、逻辑边和派生网格段数量。
- 同时有流量、告警和状态动画的线路数量。
- 模拟与真实遥测刷新频率、允许的数据延迟和图表时间窗口。
- 目标浏览器、屏幕分辨率、设备 GPU/CPU 档位和后台运行要求。

随后建立至少包含帧时间、主线程长任务、React 提交次数、绘制批次数、GPU/内存占用和视口裁剪收益的基准。性能目标不得在缺少规模数据时凭经验写死。

## 9. 验收原则

- 动画沿线路和拱桥连续运行，不在非连接交叉处跳网或误入另一网络。
- 制冷移动虚线沿普通圆角弯头、短段收紧结果和制冷拱桥连续运动；分流、汇流处按等阻力视觉流量改变方向和速度。主要/辅助线宽只表示编辑视觉层级，不暗示真实管径或水力精度。
- Off Switch 两侧的直接相邻线路均不显示动画，On 后按业务拓扑恢复。
- 电力普通子线、母线和制冷内芯的无流动物理区间直接使用当前静态显示基色压黑 50% 的最终不透明色；冷却辅助线路先由原回路/实例色与中性灰得到低对比显示基色，再执行无流量压暗。部分流动逻辑边只替换静止部分，放大后暗色抗锯齿边缘不得透出原业务色。暂停播放只冻结或移除移动虚线，不把原本有流动资格的区间改成无流动深色；主要/辅助角色不参与动画资格、方向或速度求解。
- 闭合 Switch 但链路没有算力 POD、动力 POD 或 FM 时整链不动画；有效主干旁没有 Target 的死端支路也不动画；同一 Source 的两条等长有效路径以及不同 Source 各自的最短有效路径均保留，方向冲突区间除外。
- 遥测更新不会增加编辑历史、dirty 状态或触发线路重路由。
- 典型规模下交互与动画保持稳定；超出预算时按既定策略平滑降级。
- 隐藏页、无流量网络和减少动态效果模式正确暂停或替代表达。
- 视觉质感、速度感和不同线路类型的辨识度由用户完成验收。
