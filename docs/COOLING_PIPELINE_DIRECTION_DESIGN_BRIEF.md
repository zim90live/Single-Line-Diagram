# 制冷管路静态样式、方向与模拟验证设计简报

状态：阶段 A、阶段 B 与视觉流量增量均已实现，待用户视觉与真实图纸操作验收
日期：2026-08-26
关联决策：KD-042、KD-067、KD-079、KD-080、KD-081、KD-082、KD-083、KD-086、KD-087

## 1. 目标

在现有冷却图纸拓扑、统一节点和子线单向通行能力之上，让制冷线路在编辑模式中呈现为稳定、清晰的管路，并为后续无真实遥测条件下的水流动画建立可重复验证的方向模型。

本增量分两个阶段推进：

1. 先完成静态编辑表达和既有方向配置的视觉、交互一致性。
2. 静态能力验收后，再实现运行态模拟、闭合回路判断和动态水流。

## 2. 静态管路样式

- 一次回路冷、一次回路热、二次回路冷、二次回路热和冷却通用线路首版使用同一双层管道结构，不区分主管、支管或设备支路。
- 下层管体使用 `10px` 世界空间线宽和 `#262626`，并使用 `x 0 / y 1 / 模糊 3 / #FFFFFF 50%` 的内阴影模拟体积；上层内芯使用 `2px` 世界空间线宽，颜色来自一次/二次回路冷/热预设色或实例自定义色。管径或主/子管道成为正式业务字段前，两层宽度都只承担静态视觉语义。
- 管路使用实线；下层使用平头端帽和圆角连接，上层保持圆头端帽和圆角连接。继续沿用 8px 正交路由、紧凑拱桥、统一节点和既有命中路径。
- 双层管体只属于显示几何：图元锚点端的 `10px` 下层平头直接截止于锚点中心，不再沿终端线段内缩；`2px` 内芯、逻辑线路和命中路径同样连接锚点中心。节点和交汇点端不裁短，同网络可见逻辑边先合并为一条复合管体，再统一应用一次内阴影，避免公共段及节点处重复端帽、亮边或灰色鼓包。
- 普通 90° 弯头使用首选半径 `8px` 的真圆弧；相邻线段较短时，半径收紧到不超过两侧线段长度的一半。分叉不做圆角：同一网络在该点的实际物理方向数达到 3 个及以上才视为分叉；二连节点和重合逻辑边共享的两方向弯头仍圆角。紧邻拱桥的弯点保持直角。圆角同步作用于下层、上层、选择/命中和接线预览，不修改正交路由点。
- 四类专用回路继续使用已确认预设色：一次回路冷 `#FFC800`、一次回路热 `#FF6011`、二次回路冷 `#0084FF`、二次回路热 `#00F074`；实例自定义颜色继续优先。
- 双向子线不显示箭头；单向子线继续在允许流向的逻辑目的端显示固定屏幕尺寸箭头，并向线路内部保留足够间距，避免遮挡节点或图元锚点。
- 编辑模式不播放液滴、短胶囊、移动虚线或其他水流动画。节点仍只在编辑 hover 或选中时提示，普通交叉不因此获得连通语义。
- 后续若增加真实管径、主管/支管等级或流量等级，应作为独立业务字段和增量决策，再决定是否映射到离散线宽；不得从当前拓扑连接度自动猜测主管或支管。

## 3. 三层方向模型

### 3.1 内部定义方向

每条逻辑子线稳定保存 `sourceNodeId → targetNodeId`。它用于持久化、标签端点和方向枚举，只是数据结构方向，不等于实际水流方向。移动节点、改变路由几何或旋转选区不得隐式交换两端。

### 3.2 允许流向

继续复用 `ConnectionEdge.flowDirection`：

- 未设置：双向通行。
- `forward`：只允许 `sourceNodeId → targetNodeId`。
- `reverse`：只允许 `targetNodeId → sourceNodeId`。

属性面板继续使用“双向通行 / 起点 → 终点 / 终点 → 起点”。多选值不一致时显示“多种方向”；批量修改形成一个项目事务。反转方向只切换允许方向，不交换内部端点 ID。

允许方向属于逻辑子线，不属于自由节点。拆分子线、在子线上创建节点或固化自动拐角时，新物理区间必须延续原子线的物理允许方向；节点移动、节点合并和自动重路由不得根据画面左右、上下或绘制顺序重新推断方向。

### 3.3 实际流向

运行态为每个参与动画的物理区间派生以下状态之一：

- `forward`：沿逻辑定义方向流动。
- `reverse`：逆逻辑定义方向流动。
- `stopped`：已知停流。
- `unknown`：现有拓扑和模拟状态无法唯一判断。

双向子线可出现正向或反向实际流动；单向子线的实际流动不得违反允许方向。方向冲突、方向不唯一或信息不足时保持静态，不通过线路绘制顺序、几何朝向、锚点名称或冷/热类型猜测水流。

## 4. 无遥测条件下的闭合回路模拟

### 4.1 核心判定

运行中的水泵是冷却水流驱动器：

- 水泵出口锚点是本次循环起点。
- 同一水泵入口锚点是本次循环终点。
- 只有位于至少一条“水泵出口 → 有效管路与设备 → 同一水泵入口”闭合路径上的物理区间才具备动画资格。

判定必须同时满足线路接线类型、设备内部回路、子线允许方向、阀门开启和水泵运行。不使用电力动画的最短路径裁剪，因为冷却主管可能在多个并行支路分流并重新汇流；也不再枚举所有简单路径组合。每个允许方向的物理区间分别尝试构造一条不重复节点的“出口前缀 → 当前区间 → 入口后缀”见证路径，前后段节点互斥；找到见证的区间取并集。实现分别尝试前缀优先和后缀优先的确定性最短见证，避免并联泵与多级支路使路径组合指数增长。两次均无见证时保守保持静态，不把只能往返游走的死端误判为流动。

水泵停止、模拟流量为零、阀门关闭、只有去路没有回路、死端支路或单向约束冲突时，对应区间不动画。多个运行水泵分别计算有效闭合回路后取并集；同一物理区间若得到互相矛盾且无法唯一化的实际方向，则状态为 `unknown` 并保持静态。

### 4.1.1 线路接线与设备内部水路使用不同兼容规则

- 直接接线继续按精确线路类型校验。一次冷不能直接落到一次热，二次冷不能直接落到二次热；`cooling-general` 仍只作为直接接线的兼容通用类型。
- 设备内部按水回路族连通。一次回路设备允许一次冷、一次热端口在设备内部传播；二次回路设备允许二次冷、二次热端口在设备内部传播。
- PHE 等多回路设备的一次侧和二次侧只交换热量，不交换水，内部不得跨回路连通。CT 的一次热入口与一次冷出口则属于同一水回路，可以形成闭环。
- 通用锚点结合已连接网络类型解析有效回路。设备只含一个明确回路族时可接入该族；设备同时含一次、二次明确回路时，未定回路端口不能充当跨侧桥梁。
- 普通阀门关闭时阻断上述内部传播，开启后按同回路双向连通；CV 属于止回阀，开启后也只能从稳定入口流向稳定出口，关闭时完全阻断。水泵不按普通设备内部互通，而由唯一入口/出口和运行态提供驱动。

### 4.2 水泵端口前置条件

动态阶段开始前，专用水泵素材必须在既有图元锚点编辑器中完成资产级配置：

- 图元资产的“冷却设备角色”设为“水泵”。
- 选中冷却锚点后，把“端口角色”设为“未指定 / 入口 / 出口”之一。
- 每个水泵资产必须恰好存在一个入口锚点和一个出口锚点；两者必须是相同或可解析为相同回路类型的冷却锚点。
- 为新的锚点指定“入口”或“出口”时，系统自动清除原同角色锚点，保持角色唯一，不允许同一锚点同时承担两种角色。

入口/出口是稳定业务元数据，不从锚点名称、画布方位或接线先后顺序推断。同一专用水泵素材的全部实例按 `assetKey` 继承角色；实例旋转时角色随锚点几何旋转但不互换。删除锚点或把锚点改为电力类型时同步清除该端口角色。

配置不完整时仍允许保存、接线和静态显示，关闭即时应用的锚点编辑器也不被阻止；但该水泵不驱动动画，模拟诊断必须返回“水泵入口/出口未完整配置”或对应的类型不兼容原因。

首版只允许专用水泵素材成为水流驱动器。稳定键 `generic` 的通用图元不提供实例级“水泵”角色或端口覆盖；需要参与模拟的新水泵应先建立专用素材及资产锚点模板。该边界避免同一个通用素材模板的资产级端口定义错误影响所有含义不同的通用图元实例。

建议的数据边界为：

```ts
interface AssetDefinition {
  coolingDeviceRole?: 'pump' | 'valve' | 'check-valve'
}

interface SymbolAnchor {
  flowRole?: 'inlet' | 'outlet'
}
```

`coolingDeviceRole` 决定设备的内部传播语义，`flowRole` 定义水泵与止回阀的稳定“入口 → 出口”通道。它们不会自动写入或反转相邻逻辑子线的 `flowDirection`；设备端口表达驱动或止回约束，子线方向继续表达管路允许方向。

### 4.3 模拟数据边界

当前模拟只提供验证动画所需的运行态：

- 水泵运行或停止。
- 阀门打开或关闭。
- 水泵输出功率 `0–100%`，默认 `100%`；固定基准流量为 `100 m³/h`。
- 经等阻力网络分配的有符号视觉流量，用于控制动画方向和速度。
- 通过水泵入口/出口和子线单向约束派生的实际方向。

模拟器只计算无量纲等阻力条件下的视觉流量守恒，不计算压力、扬程、真实阻力、管径或阀门开度，不宣称结果具有工程水力精度。

模拟运行态通过可替换 Provider 提供；`MockCoolingRuntimeProvider` 与未来真实遥测适配器输出相同的运行态快照。高频状态、动画相位和模拟场景不进入项目 JSON、编辑历史或 dirty；水泵端口角色和子线允许方向等编辑配置仍属于项目文档。

监控画布点击已标记的水泵或阀门只选择设备，右侧运行属性面板分别控制运行/停止、输出功率和打开/关闭；图纸结构仍不可编辑。水泵与非双状态阀门状态只存在于当前应用会话，不写入项目、IndexedDB 或编辑历史；2WV/CV 继续使用既有 On/Off 快照。资产角色不按名称或图形猜测，阀门关闭时阻断其冷却锚点之间的内部传播。详细流量模型见 `COOLING_VISUAL_FLOW_SIMULATION_DESIGN.md`。

### 4.4 首版动画表现

- 制冷动画首版不新增流光、液滴、短胶囊、发光或其他专用水流效果。监控模式保留 `10px` 深色管体和 `2px` 回路色内芯，并在具备动画资格的内芯上叠加与现有电路一致的深色移动虚线，先通过真实图纸验证方向辨识度、密度、速度与复杂分支效果。
- 首轮默认复用电路动画的运动语言和渲染参数：屏幕空间 `2px` 覆盖宽度、`6px` 实线与 `6px` 间隔、`#303238` 深色以及现有相位推进方式。物理区间的模拟流量绝对值缩放移动速度，符号决定方向；流量为零或停流时不推进动画。
- 复用范围只包含 WebGL 批量渲染骨架、移动虚线视觉参数和显示路径采样能力，不复用电力的 Source→Target 最短路径拓扑。制冷动画资格仍严格来自“运行水泵出口 → 有效闭合管路 → 同一水泵入口”，并继续执行子线允许方向、阀门门控和方向冲突规则。
- 制冷与电路保留独立样式入口。首版参数可以同值，但后续根据用户视觉验收调整制冷虚线或替换为其他水流表现时，不应连带修改电路动画。
- 动态覆盖必须沿制冷当前显示几何采样，包括普通弯头的圆弧、制冷拱桥和节点后的物理区间；不得退回原始正交折线路径。继续使用视口裁剪、单批次 GPU 绘制、逐帧仅更新时间参数、页面隐藏暂停和 `prefers-reduced-motion` 冻结相位等既有性能与无障碍边界。

## 5. 确定性验证场景

模拟场景必须可手动切换并保持可复现，不使用周期性随机拓扑状态。至少覆盖：

1. 单泵正常闭合回路完整流动。
2. 水泵停止后整条回路停流。
3. 阀门关闭后受影响区间停流。
4. 单向子线与回路方向一致时正常通过。
5. 单向子线冲突时冲突区间及失效路径不动画。
6. 主管分流并重新汇流时所有有效并行支路具备动画资格。
7. 只有去路、无法返回同一水泵入口时不动画。
8. 两台并联水泵分别启停后，有效回路并集随驱动器变化。
9. 双向管段存在相反且无法唯一化的候选方向时保持静态并返回 `unknown` 诊断。
10. CT 的一次热/冷端和 PHE 的同一侧热/冷端可闭合，但 PHE 的一次、二次侧不得串通。
11. 多级并联产生超过 `10,000` 条路径组合时仍能按物理区间求并集，不因搜索预算让整台泵失效。

## 6. 实施顺序与验收边界

### 阶段 A：静态编辑模式

- 全部冷却管路统一为 `10px` 深色带内阴影平头管体和 `2px` 圆头回路色内芯，两层均使用圆角连接。
- 四类预设色、实例颜色、选择态、命中、拱桥、节点和单向箭头保持正确。
- 拆分、节点合并、复制、保存和重新打开后允许方向不改变。
- 不新增动态水流、运行态面板或模拟 Provider。
- 2026-08-25 已实现：仅编辑模式启用双层世界空间管路；上层普通态与选择态均保持 `2px`，选择只改变现有选中色，透明命中同时覆盖固定屏幕 `20px` 与世界空间 `16px`。内阴影由各子线共用参数、按自身边界裁剪的 SVG Filter 生成。制冷拱桥使用 `16 × 8px` 真圆弧，同时保留固定屏幕底衬并增加 `18px` 世界空间画布色遮罩；单向箭头保持固定屏幕尺寸、向管路内部偏移并增加画布色轮廓。电力线路和监控模式基础线及默认 `8 × 4px` 拱桥不变。
- 2026-08-25 重叠修复：外管在图元锚点端内缩 `6px`；同网络全部可见管路合成一个复合 SVG Path 后只应用一次管体和内阴影。网络仍按逻辑顺序分组渲染，每组先画拱桥底衬、再画合并管体、最后画各逻辑边内芯与交互层，保持跨网络拱桥的上下层级。接线预览同步裁短其锚点端外管。
- 2026-08-25 第二次视觉微调：上述 `12px` 圆头外管及锚点端内缩规则已被取代。下层改为 `10px` 平头管体，锚点端内缩改为 `0`，接线预览同步；拱桥世界空间遮罩由 `15px` 改为独立 Token `18px`，命中宽度不随下层变细而缩小。
- 2026-08-25 普通弯头圆角：制冷显示路径新增 `8px` 真圆弧，短段自动收紧；物理方向数为 3 或 4 的分叉及紧邻拱桥处保持直角。物理方向按完整网络派生，因此即使视口裁剪隐藏部分线路，也不会误把分叉圆角化。下层合并管体、各逻辑边内芯、透明命中和接线预览共用相同圆角规则。

### 阶段 B：模拟监控模式

- 在锚点编辑器中增加专用水泵资产角色及入口/出口锚点角色，完成唯一性、类型兼容和缺失诊断；通用图元首版不参与驱动。
- 增加运行态 Provider。
- 实现闭合回路资格、阀门门控、方向冲突和未知方向诊断。
- 使用固定模拟场景验证流动视觉；首版在 `2px` 回路色内芯上复用电路的深色 `6px / 6px` 移动虚线效果，不制作流光。动画方向和速度由等阻力视觉流量控制，但不表达真实水力结果。
- 静态管路颜色负责回路身份，动画负责当前流动，后续结果色谱负责温度、压力或流量分析，三者不得混用。
- 2026-08-25 已实现：Schema 升至 v22，锚点编辑器可原子保存普通设备/水泵/阀门资产角色及水泵唯一入口、出口；旧 v21 项目缺省保持未分类。`MockCoolingRuntimeProvider` 提供确定性水泵、阀门和流量状态，监控画布可直接点击水泵或阀门切换当前会话状态。

## 7. 非目标

- 阶段 A 不实现监控模式动态水流、水泵角色、运行态 Provider 或闭合回路求解。
- 静态阶段不实现主管/支管线宽、真实管径或管径编辑。
- 动态阶段首版不实现物理水力求解、自动平衡、压力损失或真实遥测接入。
- 动态阶段首版不实现制冷专用流光、液滴、胶囊、外发光或粒子效果；是否替换移动虚线由首轮真实图纸视觉验收决定。
- 不把冷/热回路类型、线路几何方向或创建顺序作为实际流向依据。
